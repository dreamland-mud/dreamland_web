DreamLand Design System

One vocabulary, two surfaces: the marketing site (dreamland.rocks) and the /play web client. Aged gold and arcane purple on obsidian; parchment for reading, dark wells for the game. This page is the source of truth — live surfaces migrate onto it.

Overview

The client was built on the site's vocabulary, so the foundation is already one system — same tokens, same fonts, same gem idea. Where they drifted, the calls below pick a single canon. Tags mark where each thing lives:

both unified   site marketing surface   client /play surface   constraint not up for debate

Three constraints that override everything

1. The terminal, the map, and any panel that renders ANSI game colour stay on a dark surface — the ANSI palette and screen-reader contrast are tuned for dark ground. 2. Parchment is for reading only (articles, news, hints, modals), never for game colour. 3. Colour is never the only signal of state — about 30% of players use a screen reader or low vision.

Color both

The tokens below are shared. The ground, arcane, bright-gold and parchment sets are byte-identical across site and client. The matte-metal surface trio (--gold-metal-*) is the client's; the gems, the ink-purple cross-ref and the article face are the site's. The one thing to remember: gold splits in two — bright for text and for a selected/lit state, matte metal for resting control surfaces.

The ligature rule

Fira Code ships with programming ligatures. In reading (article bodies) they stay ON. In the terminal / map / any aligned output they go OFF (font-variant-ligatures: none) — ligatures glue ->, !=, | together and wreck ASCII maps, tables, and prompts.

The one gem recipe

Every gold control points at these three tokens, so the matte finish can never drift back to glossy.

--gem-face: radial-gradient(140% 140% at 50% 0%, --gold-metal-hi, --gold-metal 55%, --gold-metal-lo); --gem-face-hover: radial-gradient(140% 140% at 50% 0%, #6c3aa8, --arcane-deep 60%, #24123f); --gem-shadow: inset 0 1px 1px rgba(255,255,255,.6), 0 1px 2px rgba(0,0,0,.5), 0 0 0 1px --gold-deep;

Map / segmented controls gold-gem

Zoom and layer toggles wear the same matte gem as every other button; the active layer presses in and goes arcane.

Which selected-colour? Choosing one option among peers (segmented, tabs, chips) lights it in gold. A power/on state (switch on, active map layer, focus, the accent button) reads arcane.

Parchment — reading surfaces both

Aged sheet with torn/deckled edges, a thin inner rule following the contour, and a chevron ornament band along the bottom. Help articles, news, hints, side-sheet modals. Game colour gets a light-tuned ANSI remap — never the dark palette on parchment.

The rules

The short version. Break these and the thing stops being one system.

Dark vs parchmentGame colour (ANSI, terminal, map, vitals) on dark. Parchment for reading only.
Gold surface vs gold textMatte --gold-metal-* for resting control faces; bright --gold-bright/--gold for text and the selected/lit state. Darken the resting surface, never the text.
Gold vs arcane selectionChoosing one option among peers (segmented, tabs, chips) = gold. A power/on state (switch on, active map layer, focus, accent button) = arcane.
One gem recipeAll resting gold controls point at --gem-face / --gem-shadow. The arcane accent is the one lit exception, with its own recipe.
One monospaceFira Code for UI labels, code and game text. Ligatures ON in article bodies, OFF in the terminal / map / any aligned output.
FocusArcane orbit on every focusable field, both surfaces. Reduced-motion → steady glow.
Ornament is modularCorners and sides reuse at one weight; recolour with currentColor. No stretching an ornament to fit.
AccessibilityColour is never the only signal. Native <select> on narrow screens. ~30% of players read by screen reader.
